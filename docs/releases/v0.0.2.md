# wave9000 0.0.2

A small patch for the Mac: lighter playback, sound devices that come and
go, a clearer answer when the microphone isn't allowed, and install steps
that work on current macOS. Windows and Linux downloads are planned for
0.0.3.

**Download:** `wave9000-0.0.2-macos-universal.zip`, for Apple Silicon and
Intel Macs on macOS 11 or later. Unzip it and move wave9000.app to
Applications. The first time, macOS says it can't check the app: open
**System Settings → Privacy & Security** and click **Open Anyway** (on
macOS 14 and earlier, right-click → Open). Install ffmpeg
(`brew install ffmpeg`) to add files other than WAV.

## What changed

- **Playing costs less.** The playhead and meters are drawn 30 times a
  second instead of as often as the screen allows: about 17% of one core
  for the 4-track sample, down from 23%. `playback_fps` under `[look]` in
  settings.toml sets it (60 is smoother, 15 lighter).
- **A sound output that goes away stops playing.** Before, unplugging the
  output (or changing its rate in Audio MIDI Setup) left wave9000 playing
  silence with a frozen playhead. Now it stops, says so, and opens the
  output there is now. A file still being read when the rate changes is
  read again, so it doesn't play at the wrong pitch.
- **The sound thread no longer writes to the Log.** Device problems used
  to be logged straight from the audio callback's error handler, which
  can run on the sound thread. They're now only counted there, and the
  Log lists dropouts and output changes from the interface.
- **The microphone permission.** If an input gives nothing but exact
  silence for a second and a half (what macOS sends when the microphone
  isn't allowed), wave9000 says where to allow it. An input that goes away
  stops the recording and keeps what was recorded.
- **Install steps** for macOS 15 and later, where right-click → Open no
  longer opens an app from outside the App Store.

Nothing that worked before changes: projects, settings, keys, layouts and
adapters from 0.0.1 open as they did, and `playback_fps` is optional.

## Measured

On an Apple Silicon MacBook Air, release build, the 4-track sample project
at 96 kHz:

| | |
|---|---|
| Playing, 30 frames a second (default) | about 17% of one core |
| Playing, 60 frames a second (as 0.0.1 did) | about 23% of one core |
| CPU when idle | 0.0% |
| Dropouts while playing, at 30, 60 or 240 frames a second | none |

## Tested

- 46 unit tests, including how device problems are counted and cleared.
- In the app on this Mac: playing at 30, 60 and 240 frames a second, and
  the dropouts the output reports (pausing the app with a profiler makes
  CoreAudio report them, and the Log listed them).

**Not tried on a real device:** unplugging an output while playing, and
recording with a real microphone, including the silence warning. Both
need a person at the Mac.
