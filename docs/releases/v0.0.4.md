# wave9000 0.0.4

A small patch: on a Mac, wave9000 opens the sound it's handed.

## Downloads

| System | File |
|---|---|
| Mac, Apple Silicon and Intel | `wave9000-0.0.4-macos-universal.zip` |
| Windows, x64 / Arm | `wave9000-0.0.4-windows-x64.zip` / `-windows-arm64.zip` |
| Linux, x86-64 / Arm | `wave9000-0.0.4-linux-x64.tar.gz` / `-linux-arm64.tar.gz` |

Install steps are in the
[README](https://github.com/solacecasino/wave9000#readme).

## What changed

- **Sound and sessions open from Finder, the Dock and the other 9000
  apps.** wave9000 used to start empty when macOS handed it a file (a
  double-click on a `.wave`, **Open With**, `open -a`, or leaf9000 or
  text9000 passing one on). Now a sound goes onto a new track, a `.wave`
  opens, and a `.splice` brings its sound, just like a drop. A file sent
  while wave9000 is running goes to its window. Windows and Linux already
  opened files named on the command line; nothing changes there.
- **`.wave` sessions open in wave9000 by double-click** on a Mac. Sound
  files and `.splice` projects list it under **Open With** without
  changing which app opens them.
- The whole 9000 series is now five apps: text9000 (writing), splice9000
(video), wave9000 (sound), grace9000 (photos) and the new
[leaf9000](https://github.com/solacecasino/leaf9000) (comics and books, the
reader Leaf renamed). Each one hands the others' files to them.

Tried on an Apple M2: `open -a` with a WAV gave one track, a second one
sent while it ran gave a second track in the same window, and the
command line gave one track by absolute or relative path.

## Compatibility

Everything from 0.0.3 works the same: sessions, settings, keys, layouts
and adapters.
