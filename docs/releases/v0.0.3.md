# wave9000 0.0.3

wave9000 on Windows and Linux. The same app as 0.0.2 on the Mac, now with
downloads for six machines, each one built and tested on that machine.

## Downloads

| System | File |
|---|---|
| Mac, Apple Silicon and Intel | `wave9000-0.0.3-macos-universal.zip` |
| Windows, x64 / Arm | `wave9000-0.0.3-windows-x64.zip` / `-windows-arm64.zip` |
| Linux, x86-64 / Arm | `wave9000-0.0.3-linux-x64.tar.gz` / `-linux-arm64.tar.gz` |

- **Mac**: unzip it and move wave9000.app to Applications. The first time,
  macOS says it can't check the app: open **System Settings → Privacy &
  Security** and click **Open Anyway** (on macOS 14 and earlier,
  right-click → Open). `brew install ffmpeg` to add files other than WAV.
- **Windows**: unzip it anywhere and run `wave9000.exe`. SmartScreen may
  ask once, since the app isn't signed: **More info → Run anyway**. Put
  ffmpeg on your PATH (`winget install ffmpeg`).
- **Linux**: unpack it and run `./install.sh` inside to add wave9000 to
  your app menu and under **Open With** for sound files
  (`./install.sh --remove` takes it out). Sound goes through ALSA, which
  PipeWire and PulseAudio desktops route on. `sudo apt install ffmpeg`, or
  your distribution's.

## What changed

- **Windows and Linux downloads**, x64 and Arm each, and CI that builds
  and tests all six on every push: the tests run with the real ffmpeg on
  each machine (every export format written and read back), then the
  download itself is unpacked, started with a sample session, and
  screenshotted. Pushing a version tag publishes them.
- **settings.toml, keys.toml and layout.toml apply at once on Windows
  too.** The Windows build had no file watcher, so saved changes waited
  for a restart; it now sleeps in Windows' own change notification, the
  way macOS and Linux already did, at no cost while nothing changes.
- **Linux**: sound files open from the file manager (**Open With**).
- **The silent-microphone hint** names each system's own setting:
  Windows' microphone privacy switch, or a muted input on Linux.

Nothing that worked before changes: projects, settings, keys and layouts
from 0.0.1 and 0.0.2 open as they did, on every system.

## Tested

- 46 unit tests on each of the six machines, with ffmpeg.
- Each download started with the sample session and a screenshot taken
  (Windows Arm excepted: its CI machine shows a first-run privacy screen
  over everything). The Linux app menu entry is installed, validated and
  removed again.

**Not tried by a person:** the Windows and Linux builds haven't played
sound on real hardware (CI machines have no sound devices), and
recording hasn't been tried with a real microphone on any system.
